# 02 앱 프로젝트 소개 및 심사 자료

fuelog 풀로그

앱명 / 프로젝트명: fuelog (풀로그)
Pleos 기반 차량 데이터 차계부 및 공동 차량 관리 서비스

## 1 앱 한 줄 소개

차량이 읽은 주행·연료·배터리 데이터를 개인별 차계부로 연결하고, 휴대폰에서 비용을 확인하며 공동 정비까지 관리하는 Pleos 기반 차량 관리 앱입니다.

## 2 기획 배경

### 기록을 남기기 위해 반복해야 하는 입력

차량 유지비를 파악하려면 운행거리, 주유·충전 내역, 정비 시점과 비용을 꾸준히 기록해야 합니다. 그러나 이동이 끝날 때마다 수치를 옮겨 적고 영수증을 정리하는 일은 번거롭습니다. 기록이 끊기면 이번 이동에 어느 정도의 비용이 들었는지, 다음 정비가 언제 필요한지 판단하기도 어려워집니다.

### 함께 쓰는 차량에서 섞이는 개인 기록과 공동 관리

가족이나 여러 구성원이 차량 한 대를 함께 사용하면 운행 기록의 사용자와 정비를 담당한 사람이 달라집니다. 개인의 운행·지출 내역은 구분하면서도, 차량에 필요한 점검과 교체 이력은 함께 확인할 수 있어야 합니다. 차량 전체의 관리 정보와 개인별 기록을 나누는 구조가 필요한 이유입니다.

### 차량 데이터와 사용자의 확인을 연결하는 접근

fuelog는 차량이 이미 가지고 있는 거리·연료·배터리 데이터를 기록의 출발점으로 활용합니다. 차량에서는 데이터를 관측하고 기록 후보와 요약을 만들며, 휴대폰에서는 실제 지출 내용을 확인합니다. 센서 기반 추정과 실제 결제 내용을 구분해 반복 입력을 줄이면서도 기록의 근거를 유지합니다.

서비스의 중심은 차량 앱, 모바일 앱, 공통 백엔드의 연결입니다. 차량 안에서 시작한 기록이 차에서 내린 뒤에도 이어지고, 개인 차계부와 공동 정비 관리가 하나의 이용 흐름으로 연결되는 경험을 지향합니다.

## 3 앱 주요 기능 및 차량 특화 요소

### 차량과 사용자를 연결하는 QR 인증

정차 중 차량 화면의 QR을 로그인한 모바일 앱으로 확인해 차량과 계정을 연결합니다. 연결된 사용자를 기준으로 운행 기록을 관리하고, 사용자 변경이나 연결 해제 시 개인 정보 접근을 제한합니다. 공유 차량에서도 이전 사용자의 기록이 다음 사용자에게 섞이지 않도록 하는 기반입니다.

### 차량 데이터 기반 운행 기록과 비용 요약

차량의 누적 주행거리와 사용 가능한 에너지 데이터를 활용해 운행 구간을 기록합니다. 유효한 데이터가 확보된 항목에 대해 거리, 연료·전력 소모량, 연비·전비와 참고 비용을 보여줍니다. 운행 이력과 기간별 통계로 사용량을 확인하고, 종료된 운행의 추정 비용을 인원수에 따라 나누어 볼 수 있습니다. 분담액 계산은 실제 송금이나 결제 완료와 구분합니다.

### 내연기관 주유 후보와 전기차 충전 관측

내연기관 차량에서는 연료 잔량 증가를 감지해 주유 후보를 생성합니다. 전기차에서는 충전 상태와 배터리 에너지 변화를 관측해 충전 기록을 남깁니다. 반복 수신된 같은 증거가 별도 기록으로 중복 생성되지 않도록 관리하며, 감지 원본과 사용자가 확인한 보정값을 구분합니다.

주유 후보는 모바일에서 실제 금액·주유량·장소를 확인하거나 주유가 아닌 것으로 처리할 수 있습니다. 충전 기록은 관측 충전량과 조건이 충족될 때 제공되는 완속 참고요금을 표시합니다. 배터리 증가량과 충전기 결제량은 다를 수 있으므로, 추정 비용을 결제 영수증으로 표현하지 않습니다.

### 개인 차계부와 공동 정비 관리

모바일 앱에서 차량을 전환하고 운행 달력, 지출 내역, 정비 예정과 완료 이력을 확인합니다. 정비 주기는 날짜와 주행거리 기준으로 관리하고, 개인 정비와 공동 관리 항목의 접근 범위를 구분합니다. 차량 화면에서도 정비 상태를 확인할 수 있어 여러 사용자가 같은 차량의 관리 시점을 공유하도록 돕습니다.

### 위치와 연결 상태에 맞춘 신뢰도 표시

위치 활용에 동의한 경우 유효한 위치 증거를 바탕으로 주변 주유소·충전소 정보와 참고 단가를 보강합니다. 위치나 가격의 근거가 부족하면 미확인 상태로 남겨 사용자가 나중에 확인할 수 있도록 합니다. 차량 기록과 전송 대기 정보를 보존하고 재시도해, 통신 단절이 곧 기록 포기로 이어지지 않도록 설계했습니다.

### 차량 화면과 수집 동작의 분리

차량 화면은 홈, 운행, 주유 또는 충전, 정비를 중심으로 구성합니다. 주행 제한 상태를 확인해 화면 조작을 제한하고, 화면 이탈과 데이터 수집의 수명을 분리했습니다. 사용자가 시작한 수집 서비스의 상태와 중지 수단을 제공하며, 실제 차량의 절전·전원 종료 상황에서 수집을 보장하는 기능은 별도 검증 대상으로 관리합니다.

## 4 주요 사용 시나리오

### 가족 차량으로 이동한 뒤 비용을 확인하는 경우

① 사용자가 모바일 앱에 로그인하고 정차 중 차량 QR을 확인해 연결합니다.
② 차량 앱에서 운행 기록을 시작하면 지원되는 거리·에너지 데이터를 관측합니다.
③ 운행을 마친 뒤 요약에서 이동거리와 참고 비용을 확인하고 필요한 기록을 모바일 확인함으로 전달합니다.
④ 휴대폰에서 운행 달력과 지출 내역을 확인합니다. 동승자와 비용을 나눌 때는 차량 앱의 인원별 분담액 계산을 참고합니다.

### 주유 또는 충전 기록을 확인하는 경우

주유 중 연료 증가가 감지되면 차량 앱이 후보를 남기고, 사용자는 모바일에서 실제 결제 내용을 확인합니다. 전기차는 충전 상태와 배터리 증가를 관측해 충전 탭에 기록을 모읍니다. 유효한 위치와 요금 근거가 있을 때만 참고 비용을 제시하며, 위치를 얻지 못한 경우에도 에너지 관측 기록과 미확인 상태를 구분해 보여줍니다.

### 여러 사용자가 정비를 이어서 관리하는 경우

차량 관리자가 점검·교체 주기를 등록하고 구성원은 예정 항목을 확인합니다. 정비를 마치면 날짜, 주행거리와 비용을 남겨 다음 관리 시점에 활용합니다. 개인 운행 기록을 모두 공유하지 않아도 공동 정비 항목과 이력을 통해 차량 관리 상황을 이어서 파악할 수 있습니다.

## 5 개발 계획

차량 앱 fuelog, 모바일 앱 mobileappfuelog, 서버 fuelog-backend를 분리해 개발하고 있습니다. 핵심 화면과 API가 구현된 프로토타입을 기반으로, 차종별 데이터 가용성과 세 시스템의 실제 연결 품질을 검증하는 데 개발을 집중합니다.

### 프로젝트별 구현과 역할

차량 앱: Android Automotive OS 환경에서 AAOS Car API와 Pleos Vehicle SDK를 사용합니다. 거리·연료·배터리·충전 상태 관측, QR 연결, 운행·주유·충전 기록, 정비 조회, 암호화 저장과 재전송을 담당합니다. CarUxRestrictions의 현재 상태와 변경 정보를 화면 제한에 반영합니다.

모바일 앱: Android 기반 로그인과 QR 연결, 차량 선택, 운행 달력, 차계부, 주유 후보 확인·보정, 정비 이력·주기 관리를 구현합니다. Supabase Auth 로그인 정보를 공통 백엔드 API와 연계합니다.

백엔드: Java 21과 Spring Boot, MariaDB 기반으로 차량 연결, 사용자별 접근 권한, 운행 요약, 주유·충전 후보, 정비와 모바일 확인함을 제공합니다. 재전송 시 중복 처리를 막는 작업 식별자와 수정 충돌을 감지하는 버전 정보를 사용합니다.

## 5 개발 계획 계속

### SDK와 외부 데이터 검증 범위

AAOS 및 Pleos 데이터 경로별 지원 여부·권한·단위를 확인하고, FuelPercent와 주행거리, 배터리 에너지, 충전 상태의 관측 결과를 대조합니다. FusedLocation은 동의한 사용자의 필요한 시점에 활용하며, 좌표계와 측정 시각을 검증합니다. 오피넷 주유소 조회와 충전소 카탈로그·참고요금은 운영 키, 데이터 최신성, 단가 적용 시점을 확인한 뒤 제공합니다.

### 후속 개발 순서

1단계는 차량 QR 연결부터 모바일 기록 확인까지의 통합 시연을 안정화하는 것입니다. 재시도·중복 요청·사용자 변경·권한 거부·오프라인 복구를 검증하고, 전기차 충전 후보의 모바일 확인 흐름을 보강합니다.
2단계는 실차 적용입니다. 센서 흔들림, 충전 중단, 시동·절전 복귀, 앱 강제 종료와 화면 크기별 동작을 검증하고 기록 품질 기준을 조정합니다.
3단계는 초기 이용자 검증입니다. 가족·공동 사용 차량에서 기록 확인과 정비 관리의 반복 사용성을 평가합니다. 이후 선택한 비용의 공유와 정산 링크를 검토하고, 실제 결제·송금 연동은 별도 확장 과제로 추진합니다.

## 6 기대효과 및 발전 가능성

일반 운전자에게는 기록을 위한 반복 입력을 줄이고 이동 비용을 이해하기 쉽게 제공하는 가치를 줍니다. 전기차 이용자에게는 충전 관측과 운행 전력 소비를 구분해 볼 수 있는 경험을 제공합니다. 가족·공동 사용 차량에는 개인 기록을 구분하면서 정비 정보를 함께 관리하는 수단이 됩니다.

초기 검증 대상으로 가족·공동 사용 차량 30대와 사용자 약 60명을 모집하는 안을 계획합니다. 출시 후 6개월 MAU 300명과 30일 유지율 40%를 초기 검증 목표로 설정합니다. 이는 현재 실적이나 시장 규모 추정이 아닌 운영 가정이며, 모집 결과와 실제 사용 데이터를 바탕으로 조정합니다.

MAU는 월 1회 이상 기록 조회·확인 또는 정비 관리를 수행한 사용자로, 30일 유지율은 최초 차량 연결 후 30일차가 포함된 주에 핵심 기능을 다시 사용한 비율로 측정할 계획입니다. 후보 확인에 걸리는 시간, 연결 성공률, 중복·오귀속 사례와 기록 누락도 함께 측정해 편의성과 신뢰도를 평가합니다.

장기적으로 지원 차종과 정비 항목을 확대하고, 공동 사용 차량의 선택적 비용 공유 및 소규모 업무 차량 관리로 발전시키고자 합니다. 확장 시에도 개인 기록의 접근 범위를 유지하고, 관측값·추정값·사용자 확인값을 구분하는 원칙을 이어갑니다.

## 7 참고자료

제출용 자료는 차량 앱의 QR 연결·운행 요약·주유 및 충전 기록·정비 화면과 모바일 앱의 운행 달력·차계부·주유 확인·정비 화면으로 구성할 예정입니다. 시연 영상에는 차량 연결부터 기록 생성, 서버 동기화, 모바일 확인까지의 흐름을 담습니다. 공개 링크는 개인정보와 계정정보를 제거한 제출용 자료에 한해 별도로 기재합니다.

## 8 숏폼 링크

선택 제출 항목으로, 영상 게시 시 링크를 별도로 기재합니다.
